캠페인 목록은 광고 결정 API GET /v1/campaigns 가 준다. 재생 중 광고 브레이크에 닿으면 POST /v1/ad-request 로 이 중 하나가 선택되고, 그 결정이 화면(어떤 광고인지)과 데이터(어떤 campaign_id 로 쌓이는지)에 동시에 나타난다.

아직 없음. 콘텐츠를 재생하면 여기에 쌓인다.

실제 서비스에서 일어나는 사고를 이 화면에서 재현한다. 켠 뒤 광고를 한 편 더 보면, 같은 이벤트가 파이프라인 뒤쪽에서 어떻게 달라지는지 [데이터 확인] 과 대시보드에서 비교할 수 있다.

이 화면에서 일어나는 일의 순서다.

  1. 콘텐츠 선택 → session_start / content_start → user.behavior
  2. 30초(콘텐츠 시간)마다 progress
  3. 광고 브레이크 도달 → ad_request(클라이언트가 본 사실) → ad.request
  4. 같은 순간 POST /v1/ad-request → ad-decision 이 소재를 정하고 같은 트랜잭션에서 event_outbox 에 ad_response 를 넣는다 → Outbox 워커가 ad.request 로 발행
  5. 광고 재생 → impression → ad.impression
  6. 0/25/50/75/100% 지점에서 quartile → ad.quartile
  7. CTA 클릭 시 click → ad.click

자세한 흐름·스키마·활용은 저장소의 docs/01-event-flow.md, docs/02-data-stores.md, docs/03-ad-decision-api.md 참조.
